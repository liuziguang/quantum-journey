## 一、函数到底是什么

### 1.1 用数学类比（你可能最熟）

数学里你写过：

$$f(x) = x^2 + 1$$

- 你给它一个 $x$，它给你一个结果
- 你可以用任意 $x$ 反复调用它
- 你**不需要每次重新推导**这个公式

**Python 的函数就是同一个东西：一台"输入 → 输出"的机器。**

```python
def f(x):
    return x**2 + 1
```

`f(3)` → `10`，`f(5)` → `26`。一模一样的逻辑。

### 1.2 用 MATLAB 类比

你在 MATLAB 里**见过**这个：

```matlab
function y = square_plus_one(x)
    y = x^2 + 1;
end
```

Python 版：

```python
def square_plus_one(x):
    return x**2 + 1
```

**对照关系：**

| MATLAB | Python |
|---|---|
| `function` | `def` |
| `y = `（输出变量） | `return` |
| `end` | 缩进结束 |
| `x`（输入） | `x`（参数） |

**所以你不是从零学一个全新概念——你是把 MATLAB 里见过的东西搬到 Python。**

### 1.3 用生活类比

函数就像**料理机**：

```
水果  ──→  [ 料理机：square_plus_one ]  ──→  果汁
 参数                    函数                     返回值
```

- 你把水果放进去（传参数）
- 按下按钮（调用函数）
- 出来果汁（拿到返回值）
- **你不需要知道里面刀片怎么转的**——这就是函数的价值：**用的时候不用管内部实现**

## 二、为什么非要写函数？（三个真实理由）

很多人第一反应是："我把所有代码从头写到尾不就行了？"

看这个例子。假设你要算三个数的平方加一：

**❌ 不用函数：**

```python
a = 3
result_a = a**2 + 1

b = 5
result_b = b**2 + 1

c = 7
result_c = c**2 + 1
```

**✅ 用函数：**

```python
def square_plus_one(x):
    return x**2 + 1

result_a = square_plus_one(3)
result_b = square_plus_one(5)
result_c = square_plus_one(7)
```

**看起来只是少了几个字，但真正的差别在"以后"：**

| 理由 | 不用函数 | 用函数 |
|---|---|---|
| **① 改一处 vs 改三处** | 老板说"改成 x²+2"，你要改 3 个地方，漏一个就出 bug | 只改函数里那 1 行 |
| **② 名字就是文档** | 三个月后你看 `a**2+1` 得想"这是在干嘛" | `square_plus_one(3)` 一眼就懂 |
| **③ 能单独测试** | 混在一堆代码里，错了不知道哪里的问题 | `assert square_plus_one(3) == 10` 单独验证 |

**在量子计算里，第 ② 条特别重要。** 比如你要检查一个矩阵是不是酉矩阵：

```python
# ❌ 不用函数：谁能一眼看懂这行在干嘛？
is_u = np.allclose(M.conj().T @ M, np.eye(M.shape[0]))

# ✅ 用函数：名字已经把意思说清楚了
is_u = is_unitary(M)
```

## 三、函数的三个要素

每一个函数都有这三样，缺一不可：

| 要素 | 在代码里的位置 | 例子 |
|---|---|---|
| **① 名字** | `def` 后面 | `def is_unitary(M):` → 名字是 `is_unitary` |
| **② 参数（输入）** | 括号里 | `(M)` → 传进来一个矩阵 |
| **③ 返回值（输出）** | `return` 后面 | `return True` → 吐出 True 或 False |

```python
def is_unitary(M):                    # ① 名字：is_unitary  ② 参数：M
    """判断矩阵 M 是否酉矩阵"""          # 说明（可选但强烈建议）
    product = M.conj().T @ M          # 中间计算
    return np.allclose(product, np.eye(M.shape[0]))   # ③ 返回值
```

### 起名字的规矩

- 用**动词或"is/has"开头**：`normalize`、`is_unitary`、`find_max`、`count_evens`
- 全小写，用下划线连接（`square_plus_one`，不是 `SquarePlusOne`）
- **名字要能看出它干什么**。如果起不出来，说明这个函数职责不清

## 四、⚠️ 初学者最大的坑：`return` 和 `print` 不是一回事

**这是 90% 的初学者会栽的地方，单独讲。**

| | `print` | `return` |
|---|---|---|
| 干什么 | 把东西**显示在屏幕上给人看** | 把结果**交给调用它的代码用** |
| 谁能用 | 只有人的眼睛 | 程序可以继续拿它计算 |
| 函数里没有它 | 照样能跑 | **函数返回 `None`**（"什么都没有"） |

### 看这个例子

```python
def square_print(x):
    print(x**2)          # 只是显示

def square_return(x):
    return x**2          # 把结果交出去
```

**区别在于你怎么用它：**

```python
# 这个能用：
r = square_return(3)
print(r + 1)             # 输出 10

# 这个会炸：
r = square_print(3)      # 屏幕上会显示 9
print(r + 1)             # TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
```

**为什么炸？** 因为 `square_print` 只显示、不返回，所以 `r` 拿到的是 `None`。
`None + 1` 当然不行。

### 判断口诀

> **你希望别人拿着这个结果继续算吗？**
> - 要 → 用 `return`
> - 只是想看一眼 → 用 `print`

**在 `my_first_program.py` 里，所有计算函数都必须用 `return`。**
`print` 只出现在最外层（`if __name__ == "__main__":` 里），用来显示最终结果。

## 五、作用域：函数里的变量，外面看不见

```python
def f(x):
    y = x * 2        # y 是"局部变量"
    return y

f(5)
print(y)             # ❌ NameError: name 'y' is not defined
```

**为什么？** 因为 `y` 只在函数**内部**存在，函数一结束它就消失了。

这看起来是个限制，其实是**保护**：你不用担心函数里改了某个变量，把外面的东西搞乱。

**但要注意一个陷阱：**

```python
def add_one(numbers):
    numbers.append(99)      # 这会真的改掉外面那个列表！

def add_one_safe(numbers):
    new_list = numbers.copy()
    new_list.append(99)
    return new_list         # 这样才安全
```

**规则**：如果你不想改外面的东西，就在函数里**先复制一份**再改。

## 六、⭐ 核心技能：怎么把需求拆成函数

**这才是 `my_first_program.py` 真正要考的。** 很多人学会了语法，但拿到需求还是不知道从哪下手。

### 方法：把需求里的"动词"圈出来，一个动词 → 一个函数

**示例需求**：
> 1. 打印每个元素的模长
> 2. 找出模长最大的元素，打印它和它的下标
> 3. 计算所有元素模长之和
> 4. 把整个列表按模长从大到小排序

**第一步：圈动词**

| 需求 | 动词（要做的事） | 名词（要处理的数据） |
|---|---|---|
| 1. 打印每个元素的**模长** | 求模长 | 一个列表 |
| 2. 找出模长最大的元素和它的**下标** | 求最大值的下标 | 一个列表 |
| 3. 计算所有元素模长**之和** | 求和 | 一个列表 |
| 4. 按模长从大到小**排序** | 排序 | 一个列表 |

**第二步：一个动词一个函数**

```python
def abs_list(data):
    """返回 data 中每个元素的模长列表"""
    ...

def argmax(items):
    """返回最大值所在的下标"""
    ...

def total(items):
    """返回所有元素的和"""
    ...

def sort_desc(data):
    """返回按模长从大到小排序后的 data"""
    ...
```

**第三步：打印不写进函数里**

注意需求 1、2 里都有"打印"。**"打印"不是核心逻辑，是展示动作。**
把它留在最外层的 `main` 里：

```python
if __name__ == "__main__":
    data = [1+2j, 3-1j, 0+1j, 2+0j]
    print("模长列表:", abs_list(data))
    print("最大值下标:", argmax(abs_list(data)))
    print("模长之和:", total(abs_list(data)))
    print("降序排序:", sort_desc(data))
```

> **判断标准**：如果一个函数名里有 "print" 或 "display"，八成是设计错了。
> **函数负责计算，main 负责展示。**

## 九、常见困惑 Q&A

**Q：函数写得越多越好吗？**
A：不是。判断标准是"**一个函数只做一件事**"。
`is_unitary` 只判断，不打印；`sort_desc` 只排序，不求和。如果一个函数要用"和"字描述它（"排序**并**求和"），就拆开。

**Q：函数可以调用别的函数吗？**
A：可以，而且这正是它的威力。`argmax(abs_list(data))` —— 先求模长列表，再找最大值下标。

**Q：为什么要在文件底部写 `if __name__ == "__main__":`？**
A：这样别人 `import` 你的文件时，不会自动执行你的测试代码。现在记住"写了有好处"就行，原理以后再说。

**Q：函数名能起中文吗？**
A：技术上可以，但**不要**。行业惯例是英文，而且你写到简历上的项目需要能和别人交流。

**Q：我能不能先不写函数，把程序跑通再说？**
A：可以，但**不建议**。`my_first_program.py` 明确要求"至少 3 个函数"，因为**这正是它要训练的能力**。跳过等于这次任务白做。
